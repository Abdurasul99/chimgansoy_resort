## 2. «Только по ссылке» — как это обеспечено

Страницу нельзя найти, её можно только открыть по присланной ссылке.
- **Нигде на сайте нет ссылки:** её нет в меню, подвале, на главной и в карте сайта (`sitemap.xml`).
- **Закрыта для поисковиков двумя способами:**
  - `<meta name="robots" content="noindex, nofollow">` в странице;
  - заголовок ответа `X-Robots-Tag: noindex, nofollow`. Его видят и поисковики, и
    превью мессенджеров.
- **Не попадает в ответы гостям:** ИИ-консьерж о разделе не знает.

Всё это держат тесты: `src/content/__tests__/partners.test.ts`. Если кто-то добавит
страницу в карту сайта или навигацию, тест упадёт.

Проверка вживую:
```bash
curl -sI https://chimgandarbaza.uz/ru/partners | grep -i x-robots   # → noindex, nofollow
curl -s https://chimgandarbaza.uz/sitemap.xml | grep -c partners    # → 0
```

> **Что значит «только по ссылке».** Пароля на странице нет: открыть её может любой, у
> кого есть адрес. Для общей страницы этого достаточно. Персональные предложения с ценами
> будут защищены случайным ключом в адресе, а позже — отзывом ссылки из админки.

## 3. Где лежит текст и как его править

Все тексты, цифры и фото страницы лежат в одном файле: **`src/content/partners.ts`**.
Разметка (`src/app/[locale]/partners/page.tsx`) только раскладывает их по блокам. Чтобы
поменять текст, код трогать не нужно.

**Правила — их проверяют тесты:**
1. **Три языка у каждой строки** — `ru`, `uz`, `en`. Пустая строка или забытый язык —
   тест красный.
2. **У списков одинаковое число пунктов** на всех языках: права партнёра, шаги «Как начать».
3. **Фото — только ключи из `src/content/images.ts`.** Это реальная съёмка; рендеров на сайте
   нет по решению владельца. Новое фото сначала кладём в `public/images/resort/…` и
   регистрируем в `images.ts`, потом используем.
4. **Цифры — только подтверждённые**, с подписью источника (`facts.note`).
5. **Выручку и себестоимость не публикуем.** Тест ищет слова «себестоимость», «выручка»,
   «товарооборот», «млн сум».
6. **Строящееся — в блоке `territory.planned`**, без сроков.
7. **`id` программ** уникальны и латиницей: на них ссылаются якоря (`#payments`) и форма.

**Пример: поменять цифру посещаемости:**
```ts
{ value: "3 500", label: { ru: "посещений тюбинг-зоны в пиковый день", uz: "…", en: "…" } },
```
и поправить `facts.note` («По данным курорта, декабрь 2026»).

**Пример: добавить программу** — ещё один объект в `programs.items` с теми же полями:
`id`, `title`, `who`, `guest`, `rights`, `measure`. Она сама появится:
- карточкой на странице;
- пунктом «Интересует» в форме;
- названием в заявке в Telegram.

## 4. Правка через свою ИИ (Codex / ChatGPT)

Правки ИИ идут через GitHub, не напрямую на сервер. Так неудачная правка не может уронить
сайт.

### Один раз — настройка (делает Абдурасул)
1. **Доступ к репозиторию.** GitHub → `Abdurasul99/chimgansoy_resort` → Settings →
   Collaborators. Добавить аккаунт владельца с правом **Write**.
2. **Защита `master`.** Settings → Branches → Add rule для `master`:
   - ☑ Require a pull request before merging;
   - ☑ Require status checks to pass → выбрать **check**.

   Без этого ИИ сможет писать прямо в `master`.
3. **Подключение ИИ.** Владелец подключает Codex к репозиторию в настройках ChatGPT
   (Connectors → GitHub). Доступ — только к этому репозиторию.

### Каждая правка
1. **Задача ИИ.** Владелец даёт задачу (шаблон ниже). ИИ правит файлы и открывает
   пулл-реквест.
2. **Автопроверка.** GitHub сам запускает проверку **check** (`.github/workflows/check.yml`):
   типы, линтер партнёрского раздела, все тесты. Красная — ИИ исправляет в том же
   пулл-реквесте.
3. **Ревью.** Абдурасул смотрит изменения и сливает.
4. **Выкладка.** Абдурасул выкладывает (раздел 5). `git push` сам ничего не публикует.

### Шаблон задачи для ИИ
```
Репозиторий chimgansoy_resort. Правь только src/content/partners.ts
(и src/content/images.ts, если нужно новое фото).
Задача: <что поменять>.
Правила: у каждой строки ru, uz и en; фото — только ключи из images.ts;
не публикуй выручку и себестоимость; строящееся — в territory.planned.
Перед пулл-реквестом запусти: npx tsc --noEmit и npx vitest run src/content/__tests__/partners.test.ts
```

**Что через ИИ лучше не делать:**
- менять `page.tsx`, `next.config.ts`, формы и серверные функции;
- удалять файлы. `chimgan-patch` не удаляет файлы на сервере, нужен полный деплой.

Такие правки — через Абдурасула.

## 5. Выкладка

Общая инструкция — «05 — Деплой и обновление» в папке документации. Для этого раздела:

**Перед выкладкой** — те же три проверки:
```powershell
& 'C:\Program Files\nodejs\node.exe' .\node_modules\typescript\bin\tsc --noEmit
& 'C:\Program Files\nodejs\node.exe' .\node_modules\vitest\vitest.mjs run --maxWorkers=4
& 'C:\Program Files\nodejs\node.exe' .\node_modules\next\dist\bin\next build
```

**Только изменённые файлы, без удалений** — быстрая выкладка `chimgan-patch` (~4 мин):
```bash
git archive HEAD <изменённые файлы> | ssh -i ~/.ssh/chimgan_deploy root@5.189.150.167 \
  "rm -rf /root/patch && mkdir -p /root/patch && tar -x -C /root/patch && (nohup chimgan-patch /root/patch > /root/patch.log 2>&1 &)"
```
- Ждать в `/root/patch.log` строку `==> Готово` или `Build error occurred`.
- Не ждать через `pgrep -f chimgan-patch`: эта команда находит саму себя.
- Если сборка упала на загрузке шрифтов Google (`NextFontGoogleFontFileReplacer`), это сбой
  сети. Рабочий сайт не задет, просто запустить ещё раз.

**Изменения с удалением файлов** — только полный `chimgan-deploy` (инструкция 05).

**После выкладки:**
1. `https://chimgandarbaza.uz/ru/partners` открывается, правка на месте.
2. `curl -sI … | grep -i x-robots` → `noindex, nofollow`.
3. Пробная заявка через форму: в Telegram-группе появилась «🤝 Партнёрство».

**Откат на шаг назад** — `rsync` из `/var/www/chimgandarbaza.prev` (инструкция 05).

## 6. Куда приходят заявки

Форма «Обсудить партнёрство» → серверная функция `submitPartnerRequest`
(`src/app/actions/partners.ts`). Заявка уходит в три места:

| Куда | Как выглядит |
|---|---|
| Telegram — **отдельный бот @chimgandarbaza_partners_bot** | «🤝 **Партнёрство**», компания, имя, контакт, программа, задача, страница |
| Почта `INFO_EMAIL_TO` (info@ → manager@) | Тема «Партнёрство: <компания>», «Ответить» — сразу на почту партнёра |
| Журнал заявок (`/var/lib/chimgan-blob/requests`) | Как «вопрос» с пометкой «Партнёрство: <компания>», виден в боте через `/zayavki` |

### Партнёрский бот

С 11.11.2026 заявки идут не в общую рабочую группу, а через свой бот
**@chimgandarbaza_partners_bot** (`src/lib/partners-telegram.ts`). На сервере в
`/etc/chimgandarbaza.env`:

| Переменная | Что это |
|---|---|
| `TELEGRAM_PARTNERS_BOT_TOKEN` | Токен бота от @BotFather. Только на сервере — не в git и не в переписке |
| `TELEGRAM_PARTNERS_CHAT_ID` | Кому слать: id личного чата и/или группы, через запятую |

**Подключить получателя:**
1. Человек открывает бота и нажимает «Старт». Или бота добавляют в группу и пишут в ней
   любое сообщение.
2. На сервере узнать id:
   ```bash
   set -a; . /etc/chimgandarbaza.env; set +a
   curl -s "https://api.telegram.org/bot$TELEGRAM_PARTNERS_BOT_TOKEN/getUpdates" | grep -o '"chat":{"id":-\?[0-9]*'
   ```
3. Вписать id в `TELEGRAM_PARTNERS_CHAT_ID` (через запятую, если несколько).
4. `systemctl restart chimgandarbaza` — переменные читаются при старте.

**Страховка.** Пока токена или чата нет — или бот не смог доставить ни в один чат (бота
удалили из группы, его заблокировали), — заявка уходит в общую рабочую группу через
служебного бота. Лид не теряется.

**Если токен утёк** — @BotFather → `/revoke`, новый токен вписать в env и перезапустить
службу.

**Сейчас (11.11.2026):** `TELEGRAM_PARTNERS_CHAT_ID=-5315087000` — группа «ChimganDarbaza
Partners».

> **Ловушка — смена id группы.** Если группе включить историю для новых участников,
> сделать её публичной или добавить администраторов с особыми правами, Telegram превращает
> её в супергруппу, и id меняется на `-100…`. Старый id перестаёт работать. Заявки при этом
> не теряются: уходят в общую группу, а в журнале службы появляется «партнёрский бот не
> доставил». Новый id — снова через `getUpdates` (в ответе будет `migrate_to_chat_id`).

**Что форма требует от партнёра:**
- компанию и имя;
- телефон **или** рабочую почту;
- согласие на обработку персональных данных. Согласие с офертой для гостей сюда не
  относится.

**Защита и надёжность:**
- ловушка для ботов — скрытое поле;
- длина полей ограничена;
- текст экранируется;
- программа принимается только из списка.

Если заявка не дошла ни в Telegram, ни на почту, партнёр видит ошибку с телефоном курорта,
а не ложное «спасибо».

## 8. Если что-то не так

| Симптом | Что делать |
|---|---|
| Проверка на GitHub красная | Открыть её лог. Чаще всего — забытый язык или неверный ключ фото, тест пишет путь к полю (`partnersPage.programs.items[2].guest.uz`) |
| Страница 404 после выкладки | Файла `src/app/[locale]/partners/page.tsx` нет на сервере — выложить его; `journalctl -u chimgandarbaza -n 50` |
| Правка не видна | Страница кэшируется до 5 минут. Подождать или проверить, что выкладка дошла до «Готово» |

| Страница появилась в Google | Проверить `X-Robots-Tag`. Удалить адрес — через Search Console → «Удаления» |

## 9. Админка партнёров и персональные ссылки

### Вход
`https://chimgandarbaza.uz/ru/adminpartners`. Пароль — `PARTNERS_ADMIN_PASSWORD` в
`/etc/chimgandarbaza.env` (копия — в папке «Инструкия Сайта Chimgan Darbaza», файл
`chiimganpasswords.txt`). Пароль владельца `ADMIN_PASSWORD` тоже пускает.

Защита (админка на публичном домене, поэтому строже обычной панели):
- секунда задержки на каждую попытку;
- 5 неверных паролей подряд с одного адреса — блокировка на 15 минут. Адрес берётся из
  `X-Real-IP`, его ставит nginx и подделать нельзя;
- вход живёт 12 часов. Смена пароля сразу закрывает все старые входы;
- страница закрыта от поиска (`X-Robots-Tag`, `noindex`) и не кэшируется
  (`Cache-Control: private, no-store`). В `robots.txt` её нет намеренно: там она только
  подсказала бы, где искать форму входа.

**Сменить пароль:** новое значение в env → `systemctl restart chimgandarbaza` → обновить
`chiimganpasswords.txt`.

### Как работать
1. **«+ Новое предложение».** Компания, контакт (виден только в админке), вступление,
   программы, до 3 пакетов (название, цена в сумах без НДС — пусто = «по запросу»,
   «что входит» строками, примечание), срок действия, статус.
2. **«Создать ссылку».** Получаете адрес вида `/ru/partners/o/uzum-k7Qa2x`. Есть варианты на
   ru, uz и en — кнопки «Копировать».
3. **Логотип** — PNG, JPEG или WebP, лучше с прозрачным фоном. В браузере уменьшается до
   600 px: nginx на этом домене принимает запросы до 1 МБ.
4. **Отправить ссылку компании.**

### Что приходит в группу «ChimganDarbaza Partners»
| Событие | Сообщение | Ограничение |
|---|---|---|
| Компания открыла ссылку | «👀 Uzum впервые открыл предложение» / «снова открыл», число открытий | не чаще раза в 30 минут на ссылку |
| Нажала «Запросить договор» | «🤝 Uzum просит договор», пакет и цена | не чаще раза в 10 минут на ссылку |

**Как считаются открытия:**
- Открытие засчитывается из браузера через 3 секунды на видимой странице. Превью ссылки в
  Telegram или WhatsApp открытием не считается.
- Ваши собственные открытия, пока вы вошли в админку, не считаются.

**Статус в админке меняется сам:**
- «Отправлено» → «Открыто» при первом открытии;
- → «Переговоры» после запроса договора;
- «Договор» и «Отказ» вы ставите сами, автоматика их не откатывает.

### Ссылка ушла не тому / сделка закрыта
- **«Отозвать ссылку»** — страница перестаёт открываться. «Вернуть ссылку» — снова
  работает.
- **«Новый адрес»** — старая ссылка умирает, новую нужно отправить заново.
- **«Удалить»** — совсем, вместе с логотипом.

Отозванная, удалённая или выдуманная ссылка показывает «Страница не найдена» — без
названия компании и цен.

> Код ответа у такой страницы — 200, а не 404. Это общая особенность сайта: из-за экрана
> загрузки (`[locale]/loading.tsx`) Next начинает отдавать страницу раньше, чем узнаёт,
> что её нет. Так ведут себя все «не найдено» на сайте. Содержимое не утекает, страница
> закрыта от индексации.
