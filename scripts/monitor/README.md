# Сторож заявок и брони

Появился 19.11.2026 после недели, когда заявки не доходили в группу (она
сменила ID), а узнали случайно. Пишет **только о сбоях** с заявками и бронью:
никаких «я жив» и сводок.

**Все сообщения о сбоях — только письмом. В Telegram не уходит ничего:** ни в
группу заявок, ни в личные чаты, ни партнёрским ботом (владелец, 20.11.2026).
Группа заявок получает только сами заявки.

## Два уровня

1. **Сайт, сразу** (`src/lib/alerts.ts`). Заявка не дошла в группу заявок →
   письмо с заявкой целиком и причиной. Группа сменила ID → сайт сам шлёт
   заявки в новую, в группу об этом не пишет.
2. **Сторож на сервере, каждые 10 минут** (`chimgan-monitor.py`), от сайта
   не зависит:
   - журнал сайта: заявка не дошла в группу и письмо с ней тоже не ушло,
     письмо с заявкой на почту не ушло, у гостя не отправилась форма после
     выкладки, группа сменила ID (одно письмо на каждый новый ID);
   - сайт открывается и сервис запущен (иначе заявку оставить негде).

Сертификаты и связь с Exely сторож не проверяет: 20.11.2026 владелец попросил
писать только о сбоях с заявками (до этого приходило «не удаётся проверить
сертификат Exely» из-за обрыва связи).

Длительный сбой — письмо при начале, напоминание раз в 2 часа и
«восстановлено». События журнала — одно письмо на 10 минут, где они были.

## Куда приходят письма

`ALERT_EMAIL_TO` в `/etc/chimgandarbaza.env` (адреса через запятую) — его
читают и сайт, и сторож. Тема письма всегда начинается с **`[Сбой заявок]`**.

Пока домен `chimgandarbaza.uz` не подтверждён в Resend, письма уходят с
`onboarding@resend.dev`, и Resend доставляет их **только владельцу аккаунта —
`manager@chimgandarbaza.uz`**; на любой другой адрес отвечает 403. Поэтому:
сначала письмо пробуется на `ALERT_EMAIL_TO`, при отказе — то же письмо в
ящик заявок (`RESERVATIONS_EMAIL_TO`). Чтобы оно попало на личную почту,
в ящике `manager@` нужен фильтр пересылки (Google Workspace):

1. Настройки → «Пересылка и POP/IMAP» → «Добавить адрес пересылки» →
   личный адрес → подтвердить кодом из письма, пришедшего на личную почту.
2. Поиск: `subject:"Сбой заявок"` → «Создать фильтр» → «Переслать на» этот
   адрес (по желанию — «Пропустить входящие»).

Когда домен подтвердят в Resend и `BOOKING_EMAIL_FROM` вернут на адрес
домена, письма пойдут прямо на `ALERT_EMAIL_TO` — без правок кода, фильтр
можно будет убрать.

## На сервере

| Что | Где |
|---|---|
| скрипт | `/usr/local/bin/chimgan-monitor` |
| расписание | `/etc/cron.d/chimgan-monitor` (каждые 10 минут) |
| состояние | `/var/lib/chimgan-monitor/state.json` |
| журнал сторожа | `/var/log/chimgan-monitor.log` |

Обновить после правки скрипта:

```bash
cat scripts/monitor/chimgan-monitor.py | ssh root@5.189.150.167 \
  'install -m 755 /dev/stdin /usr/local/bin/chimgan-monitor'
```

Проверить без отправки — что ушло бы за период:

```bash
python3 -c 'import json,datetime; json.dump({"last_run": datetime.datetime(2026,11,18).timestamp()}, open("/root/mon-test.json","w"))'
MONITOR_STATE=/root/mon-test.json /usr/local/bin/chimgan-monitor --dry-run
```

`--init` — записать «сейчас» как точку отсчёта, не отправляя прошлое.

## Что не тревожит

- «Failed to find Server Action "x"» (и «y», «r2s», пустой ID) — сканеры
  уязвимостей Next.js, не гости. Тревога — только на настоящий ID действия
  (длинный hex): это гость, у которого страница была открыта до выкладки.
- «[telegram] sendMessage failed» сам по себе: так падает и ответ гостю в
  боте-консьерже. Заявки сайт сам шлёт письмом при сбое группы; сторож пишет,
  только если и это письмо не ушло.
