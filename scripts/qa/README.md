# QA-проверки сайта

Инструменты полного QA-прохода от 17.11.2026. Запускать из корня репозитория.

## Локальный сервер — без отправки заявок

Формы проверяются с настоящей отправкой, поэтому каналы доставки и база
выключаются переменными окружения — иначе тестовые заявки уйдут менеджерам:

```bash
npm run build
TELEGRAM_STAFF_BOT_TOKEN="" TELEGRAM_PARTNERS_BOT_TOKEN="" TELEGRAM_ADMIN_CHAT_ID="" \
RESEND_API_KEY="" BLOB_READ_WRITE_TOKEN="" BLOB_DIR=/tmp/qa-blob \
DATABASE_URL="postgres://x:y@127.0.0.1:1/none" DATABASE_URL_UNPOOLED="postgres://x:y@127.0.0.1:1/none" \
npx next start -p 3123
```

Без базы ресторан и правки из админки показывают значения по умолчанию из
`src/content`, а видео домиков (`/blob/...`) отвечают 404 — это не ошибки.

## Инструменты

| Скрипт | Что делает |
|---|---|
| `crawl.cjs <base> <out> [ширины] [языки] [--content-only] [--no-images]` | 33 страницы × языки × ширины (по умолчанию 9: 320–1920). Ищет выход за край экрана и его источник, обрезанный текст, битые картинки, ошибки JS и запросов, число H1, `lang`, русский текст на `/uz` и `/en`, сырые ключи. Пишет `report.json` и скриншоты. |
| `summarize.cjs <out>/report.json [виды]` | Сводка отчёта: одинаковые проблемы сгруппированы по ширинам и страницам. |
| `flows.cjs <base> [папка для снимков]` | Сценарии гостя: коды 404, фирменная 404, ошибки гидратации, мобильное меню и Escape, переключение языка, галерея и просмотр фото, запасной экран /bron без Exely, консьерж, форма заявки (пустая не уходит; после ошибки поля не стираются). |
| `contrast.cjs <base> [страницы]` | axe color-contrast на 1440 и 390 px, сгруппировано по цветам. |

На боевом сайте (`https://chimgandarbaza.uz`) `flows.cjs` форму заявки **не
отправляет** — она ушла бы менеджерам в Telegram. Для живого сайта обход
лучше запускать с `--content-only --no-images` и одной шириной — меньше
нагрузка на сервер.

Штатные e2e проекта: `npx playwright test` (тоже против боевого сайта,
только чтение) — доступность (axe), SEO, заголовки безопасности, ссылки,
вёрстка и скорость на телефоне, планшете и компьютере.

## Если vitest пишет «Timeout waiting for worker to respond»

Это перегрузка машины, а не код: запуск `node` занимает секунды вместо долей
секунды (браузер, антивирус, обновления Windows). Подождать и повторить.
